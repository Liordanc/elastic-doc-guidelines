# Accessibility and inclusivity guidelines

Elastic documentation must be accessible and inclusive for all users.

## Accessibility principles

- Make content scannable with clear structure
- Add alt text for images and media
- Use plain language
- Use parallel structures in lists
- Use meaningful link text
- Use device-agnostic language
- Avoid directional language (above, below, left, right)
- Use alt text format: `![Description of image](image.png)`

## Inclusive language

- Write for international audiences
- Use simple, clear language
- Avoid ambiguous words with multiple meanings
- Avoid idioms and regionalisms
- Avoid Latin abbreviations (use "for example" not "e.g.")
- Avoid violent or ableist terminology
- Avoid superhero terms (rockstar, wizard)
- Use gender-neutral language

## Testing for accessibility

- Navigate with only a keyboard
- Test on mobile devices
- Use a screen reader
- Turn off sound to verify visual content

## Preferred terminology

| Avoid | Use instead |
|---|---|
| Click, tap | Select, choose |
| Above | Preceding, previous |
| Below, under | Following, further, later |
| See | Check, refer to |
| Hear | Learn |
| Guys | Folks, team |
| Mankind | Humanity |
| Policeman | Police officer |

## Important notes

- All audiences include users with disabilities
- Content must work with assistive technologies
- Scannability helps all users, not just those with disabilities
- Plain language benefits non-native English speakers
- Tests regularly to ensure accessibility
